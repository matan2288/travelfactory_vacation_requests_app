# Vacation Management — Backend

REST API for vacation requests built on **Node.js 20+, strict TypeScript, [Common Event Framework](https://www.npmjs.com/package/commoneventframework) (CEF), TypeORM and PostgreSQL**. Requesters submit requests; validators approve or reject them.

## Quick start

Prerequisites: Node.js 20+ and Docker. PostgreSQL runs in Docker, so no other database server is needed.

```bash
cd backend
npm install
cp .env.example .env          # then set JWT_SECRET to a random 32+ character string
npm run db:up                 # start PostgreSQL 16 on localhost:5432
npm run db:migrate            # create schema, enums and constraints
npm run db:seed               # demo users + sample requests (idempotent)
npm run dev                   # API on http://localhost:8888, Swagger UI at /doc
```

## API

Send `Authorization: Bearer <token>` on every route except login. Dates are `YYYY-MM-DD` strings, enum values are uppercase, and responses are camelCase.

| Method & path | Role | Description |
| --- | --- | --- |
| `POST /auth/login` | public | `{ email, password }` → `{ user, token, expiresAt }` |
| `GET /auth/me` | any | Current user |
| `GET /users?role=REQUESTER` | validator | Users for the requester filter |
| `POST /vacation-requests` | requester | `{ startDate, endDate, reason? }` → `201` with a PENDING request |
| `GET /vacation-requests/me` | requester | Own requests, newest first |
| `GET /vacation-requests?status=&userId=&search=&page=&pageSize=` | validator | `{ items, total, page, pageSize, totalPages }`; pending first, then newest; `pageSize` is capped at 100 |
| `PATCH /vacation-requests/:id/approve` | validator | PENDING → APPROVED |
| `PATCH /vacation-requests/:id/reject` | validator | `{ comment }` (required) → PENDING → REJECTED |
| `GET /team-planning?year=&month=` | any | Every user with their PENDING/APPROVED requests in that month; reasons and comments are omitted |

Errors always look like `{ code, message, details? }`. `details` maps fields to messages for validation errors.

| Status | Codes |
| --- | --- |
| 400 | `VALIDATION_ERROR` (bad JSON, bad fields, past start date, end not after start, missing comment) |
| 401 | `UNAUTHORIZED` (missing, invalid or expired token; wrong credentials) |
| 403 | `FORBIDDEN` (wrong role) |
| 404 | `NOT_FOUND` |
| 409 | `OVERLAPPING_REQUEST`, `REQUEST_NOT_PENDING` |

```bash
TOKEN=$(curl -s -X POST localhost:8888/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"alex.requester@company.internal","password":"demo1234"}' | jq -r .token)

curl -s -X POST localhost:8888/vacation-requests -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"startDate":"2027-02-01","endDate":"2027-02-05","reason":"Ski trip"}'
```

## Architecture

Feature-first layered design: **CEF route → input parser → handler → command/query → repository → PostgreSQL**.

```text
src/
├── index.ts                  CEF/Lambda entry: route dispatch, error → HTTP mapping, local dev server
├── root.yaml                 OpenAPI routes with x-handler / x-inputParser (also served at /doc)
├── generated/                HandlerRegistry.ts (generated by codegen, do not edit)
├── config/env.ts             zod-validated environment
├── shared/                   AppError hierarchy, domain-event dispatcher, HTTP + date helpers
├── database/                 data source, entities, migration, migrate + seed scripts
├── auth/                     login / me, JWT service, guard (authentication + roles)
├── users/                    user DTO mapper, validator-only user list
├── vacation-requests/        schemas, commands, queries, events, repository, DTO mapper, handlers
└── team-planning/            monthly calendar query
```

- **CEF as the HTTP/Lambda adapter.** `root.yaml` declares each route's `x-inputParser` and `x-handler`. Parsers authenticate first, then validate with zod, so anonymous callers always get 401 before any 400. Handlers stay thin. The same `handler` export runs on the CEF dev server, in tests, and on AWS Lambda.
- **Commands and events.** Writes go through `CreateVacationRequestCommand`, `ApproveVacationRequestCommand` and `RejectVacationRequestCommand` handlers. Each one publishes `VacationRequestCreatedEvent`, `VacationRequestApprovedEvent` or `VacationRequestRejectedEvent` **after** the write commits. Reads go through query functions. An audit logger subscribes to every event. Listener failures are logged and never fail the request.
- **Business rules are enforced at the strongest layer available.**
  | Rule | Where |
  | --- | --- |
  | End date after start date | Command handler + `CHECK (end_date > start_date)` |
  | No overlapping requests | PostgreSQL `EXCLUDE USING gist (user_id WITH =, daterange(start_date, end_date, '[]') WITH &&) WHERE status IN ('PENDING','APPROVED')`. This is race-safe under concurrent submissions, and rejected requests free their dates. |
  | Approved requests are immutable | No update endpoint. Transitions use `UPDATE … WHERE status = 'PENDING'`, which is atomic, so two validators cannot both decide. |
  | No past start dates | Command handler |
  | Rejection requires a comment | zod + command handler + `CHECK` constraint |
  | Only validators decide | Guard on every decision route, using the role signed into the JWT |
- **Security.** Passwords are stored as bcrypt hashes and the column is excluded from default selects. Login returns one generic error for unknown emails and wrong passwords, and compares against a dummy hash so timing does not reveal which emails exist. JWTs are HS256-only, carry only the user id and role, and are short-lived. Tokens and credentials are never logged.
- **Dates.** PostgreSQL `date` columns are kept as `YYYY-MM-DD` strings (the pg DATE parser is overridden), so there is no timezone drift. `daysCount` is computed as inclusive calendar days, matching the frontend.
- **Indexes.** `(user_id, created_at DESC)` serves "my requests", `(status, created_at DESC)` serves the validator queue, and the exclusion constraint's GiST index serves overlap checks.

## Known limitations

- **Events are in-process and not durable.** A crash between commit and publish loses the event. In production, use a transactional outbox table drained by a worker.
- **"Today" uses the server timezone.** Near midnight, a user in another timezone may see a few hours of leniency or strictness on the past-date rule.
- **CEF dev-server preflight omits `PATCH`.** CEF's built-in `OPTIONS` handler hard-codes its allowed methods. Browsers should reach the API through the frontend's same-origin Vite proxy, as the integration plan specifies. API responses themselves do advertise `PATCH`.
- **The `cef-gen-handlers` binary does nothing when run through npm's `.bin` symlink** (a CEF bug: it compares the unresolved symlink path to its real path). `npm run codegen` therefore calls the script file directly.
- **Stateless JWT.** There is no refresh token or server-side revocation, and logout simply drops the token on the client. Login has no rate limiting.
- Team planning returns every user, which is fine for one team. Larger organisations would need team scoping and pagination.
- Seed requests use fixed 2026 dates that mirror the frontend mock data.
